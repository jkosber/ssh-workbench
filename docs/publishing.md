# Future publishing readiness

The private development repository is the technical source of truth. Personal
planning, questions and troubleshooting reflections belong in Obsidian. Neither
the application nor its documentation is a finished portfolio case study or a
homelab guide.

## Portfolio checklist

- [ ] Describe only implemented behavior and distinguish agent work from
  Jadon's reviewed contribution and understanding.
- [ ] Link meaningful changes, test results and sanitized screenshots captured
  from actual runs; label mockups and planned behavior.
- [ ] Explain the problem, one or two design choices and verified limitations.
- [ ] Remove private paths, addresses, host aliases, account details and secrets.
- [x] Choose a license: MIT, decided on 2026-10-20.
- [ ] Obtain human approval for the exact content, destination and any
  repository visibility change before publishing.

## Homelab guide/helper checklist

- [ ] Base instructions on implemented features and approved repeatable tests.
- [ ] State prerequisites, tested operating systems and the native SSH boundary.
- [ ] Use fictional examples and document expected results, failure handling
  and safe recovery without weakening authentication or host-key checks.
- [ ] Have Jadon review the steps and privacy before publishing any guide or
  helper content. Building a guide site is a separate task.

## Evidence worth collecting

Retain dated validation notes, relevant commit links, CI runs, short explanations
of decisions and approved usability observations as development progresses.
Keep private evidence outside Git until sanitized. Record questions Jadon wants
to investigate; do not invent reflections, test results or claims of experience.

Publication requires deliberate human approval even after these checks pass.
The project has no site, release automation or public publication.
